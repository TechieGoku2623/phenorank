# Phase 0 research memo — phenorank

This memo is generated by `research/phase0/render_docs.py` from harness
`results.json` files. Narrative is the template; every quantitative claim is
substituted from those files. Re-run `make research` after changing a harness.

**Safety.** This project is research / hypothesis generation. It is not a
diagnosis, not a medical device, and not clinical advice. Every response
payload states that. No patient-identifiable data is committed or processed
in Phase 0.

---

## §1 Problem statement

A clinician writes a paragraph about a child. The next job is to turn that
paragraph into a short list of genes or diseases worth testing, with a
reason for each rank. Today that step is a person paging through HPO and
OMIM, or a black-box web tool that does not say which phenotypes drove the
list, which expected findings were absent, or what one more test would
change.

The people who pay are families waiting on a gene panel and labs that
sequence the wrong panel first. The obvious fix — "just run Exomiser /
Phenomizer on the HPO list" — assumes the HPO list already exists and is
polarity-clean. Real notes say "no seizures" and "possible ataxia." Treating
those as positive findings ranks the wrong disease.

This repo extracts ontology-constrained HPO terms (never a term outside the
committed subset), scores candidates with Resnik and a Phenomizer-style
measure, and returns a ranked hypothesis list with driving phenotypes,
expected-but-absent findings, and the additional test that would change the
ranking. It does not diagnose.

## §2 Prior art

| Tool | What it does | Gap |
| --- | --- | --- |
| [Phenomizer](https://www.human-phenotype-ontology.org/) (Köhler et al. 2009) | Symmetric semantic similarity + p-values over HPO | Assumes a clean term list; no negation |
| [Exomiser](https://github.com/exomiser/Exomiser) | Phenotype + variant combined ranking | Needs genotypes; not a note-to-term engine |
| [LIRICAL](https://github.com/TheJacksonLaboratory/LIRICAL) | Likelihood ratio on HPO + variants | Same input assumption |
| [ClinPhen](https://github.com/bejerano-lab/ClinPhen) / [Doc2HPO](https://github.com/stormliucong/doc2hpo) | Note → HPO | Weak negation story; not tied to a replayable ranker |
| [Monarch / HPO](https://hpo.jax.org/) | Ontology and annotations | Inputs, not a ranking trail |
| Panel App / commercial "phenotype suggest" | Gene lists from checkboxes | Closed; no expected-but-absent object |

Phenomizer already ranks from a term list. Another engine is still worth
building because the failure is upstream (negation, uncertainty, unmapped
terms) and downstream (a typed explanation, not a p-value page). The product
is the trail, not a new similarity.

## §5 Evaluation design

Hold-out (Phase 3, not run here): a pinned set of de-identified vignettes
with expert-assigned disease labels, if an IRB corpus exists. Until then the
committed simulated patients are the only labeled set.

Metrics, declared before any model is built:

- Extraction P/R/F1 by polarity (positive / negated / uncertain)
- Unmapped-term recall (must never silently map)
- Ranking top-1 / top-3 vs known disease labels
- Baseline: naive extractor + Resnik
- Second baseline: polarity-aware + Resnik
- Default: polarity-aware + the winner of §4.2
- Noise curve from `noise_degradation`

Split: committed files. Seed 0. No random reshuffle in CI.

**Failure condition (written before the answer):** the project fails if, on
the labeled hold-out, polarity-aware ranking does not beat the naive
extractor on cases that contain a negated distinctive finding, **or** if any
term outside the committed subset is emitted as an HPO id, **or** if
nonspecific input is returned as a high-confidence singleton.

## §7 Risks

| Risk | Type | Mitigation or acceptance |
| --- | --- | --- |
| Toy ontology overstates ranking accuracy | Data | Accepted for Phase 0. Memo says so. Phase 3 replaces profiles with a dated public annotation file. |
| Lexicon misses lay variants | Technical | `lay.txt` is the teaching case; expansion is Phase 2. |
| Users read a rank as a diagnosis | Legal | Disclaimer on every payload, CLI, and README. |
| OMIM reuse limits | Legal | Do not redistribute OMIM narratives. IDs and designed profiles only. |
| Phenomizer already exists | Scope | Accepted. The gap is polarity, unmapped handling, and a typed explanation. |
| Noise collapse on real notes | Technical | `noise_degradation` is the gate. Harsh-cell result is in §4.3. |

### Highest-risk technical unknowns going into Phase 1

1. Whether a dated public HPO annotation file reproduces the
   Resnik-vs-Phenomizer gap measured on these ten profiles.
2. Whether real-note negation is regular enough that rules stay above the
   naive baseline (live-note F1 **unmeasured**).
3. Whether expected-but-absent suggestions are specific enough that a
   clinician would order the named test.
